# The own world on your PC: look at it, pregenerate it, upload it

The own world (design/architecture/own-world.md) is generated by the mod from the map's rasters. Until
`own-world-switch` is merged, it exists only on a local server. This page is the loop from "look at it" to "the staging
server runs the pregenerated world". Everything here runs in Git Bash on the PC, with the tools of docs/server.md.

## 1. Look at it (any time, nothing on staging changes)

```bash
git fetch && git switch own-world-switch
export TTL_LOCAL_DIR=/c/ttl/own-world          # a NEW empty folder: your Lerfing test server stays as it is
bash tools/local.sh up                          # first time ~5 min (installs the pack, builds ttl-portals)
```

- Join `127.0.0.1:25565` with the pack's client (the Prism instance); `/gamemode spectator` and fly.
- The web map: `http://127.0.0.1:8100` (BlueMap renders what has been generated).
- Wait for the start-up placements before judging: the log shows `tempest placed`, `dwargon placed`, 7 landmarks and
  every build (`grep -E '\[ttl\] [a-z_]+ placed' $TTL_LOCAL_DIR/server/logs/latest.log | wc -l` reaches 39).
- Only the sites are generated at first; walking or flying generates the rest, or pregenerate (step 3).

## 2. Change the look, see it again

Edit `world/map.svg` (geography) or paint `world/paint/*.png` (height, roughness, biome; world/README.md), then:

```bash
python -I tools/world/build.py --apply          # rasters into pack/config/ttl/world/, anchors follow the map
python -I tools/gen_data.py && python -I tools/gen_map.py
bash tools/local.sh down
mv "$TTL_LOCAL_DIR/server/world-ttl" "$TTL_LOCAL_DIR/old-world-$(date +%H%M)"   # chunks keep the old terrain
bash tools/local.sh up
```

Already generated chunks never change: a new look needs a new world (the `mv`, never a delete).

## 3. Pregenerate everything (once the look is final)

Use the **staging server's seed**, or the chunks the server makes later at the edges will not match:

```bash
bash tools/server.sh rcon "seed"                # e.g. Seed: [-4172144997902289642]
bash tools/local.sh down
mv "$TTL_LOCAL_DIR/server/world-ttl" "$TTL_LOCAL_DIR/old-world-seed"
TTL_LOCAL_SEED=-4172144997902289642 bash tools/local.sh up    # wait for the 39 placements again
bash tools/local.sh rcon "neoforge generate start -256 70 -256 400"
bash tools/local.sh rcon "neoforge generate status"           # until "No pregeneration currently running"
```

The design box is 12,800 x 10,752 blocks (the continent plus 1,200 blocks of sea): radius 400 chunks around its middle
covers it, about 640,000 chunks. Expect 1-4 hours and several GB. Then check it:

```bash
bash tools/local.sh rcon "ttlsite check all"     # 38 of 38 sites OK
TTL_LOCAL_DIR=$TTL_LOCAL_DIR python -I tools/world/compare_design.py    # needs the bridge: below
```

`compare_design.py` uses the build bridge: set `"enabled": true` in `$TTL_LOCAL_DIR/server/config/ttl/bridge.json`
(local only) before the start. Pictures land in `world/build/compare/`.

## 4. Upload it (a night with nobody online; Yasuke's call)

Order matters: the server must run the same map and mod as the uploaded world.

1. Merge `own-world-switch` into main (after its open items: HANDOFF), release ttl-portals (`python tools/release_mod.py`).
2. `bash tools/local.sh down`, then upload (resumable; checks seed, map and checksums, refuses otherwise):

   ```bash
   bash tools/import_world.sh --src "$TTL_LOCAL_DIR/server/world-ttl" --manifest --dry-run
   bash tools/import_world.sh --src "$TTL_LOCAL_DIR/server/world-ttl"
   ```

3. `bash tools/server.sh deploy`: the restart swaps the world in (the old one goes to ttl-backup), the placers run, then
   `ttlsite check all`. The script prints the log lines to watch; rollback is in docs/server.md "World import".

Without an upload the server pregenerates the continent itself at night (docs/server.md "Night pregeneration"); the
upload only makes it complete, and checked by you, on the first day.
